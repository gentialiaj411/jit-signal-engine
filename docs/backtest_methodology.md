# Backtest Methodology

## Data alignment
- Input is canonical `mf::core::BookEvent` records from the market-data-handler journal.
- Events are processed strictly in journal order.
- For each event at time `t`, the runner updates per-symbol market state (`bid`, `ask`, `last_price`, `volume`) and then evaluates the compiled signal program once for that symbol.
- Mid-price series per symbol is derived as `(bid + ask)/2` when both are present, otherwise the available side, otherwise `last_price`.

## Forward returns
- For horizon `h` ticks, forward return is:
  - `r_t(h) = (mid_{t+h} - mid_t) / mid_t`
- IC at horizon `h` is Pearson correlation between `signal_t` and `r_t(h)` over all valid `(symbol, t)` pairs.
- Horizons used: `h ? {1, 5, 30}` ticks.

## Interpreting current IC magnitudes
Current IC values on the recorded 500k-ITCH-event runs are on the order of `1e-4`, which is at the noise floor for this setup. Non-trivial IC would require longer forward-return horizons, return-based targets instead of raw microprice deltas, or tighter universe filtering to reduce cross-section noise. This framework is validating methodology correctness and determinism, not claiming signal alpha.

## Look-ahead avoidance
- Signal value at index `t` is computed immediately after ingesting event `t`.
- Forward return uses `mid_{t+h}` only during post-processing after the full stream pass.
- The runtime evaluation path does not consume any future events while producing `signal_t`.

## Determinism
- Determinism test executes the runner twice with identical:
  - journal path
  - signal program path
  - max-events
  - seed
- The test asserts identical IC sections in `ic_report.json` across reruns.

## Known limitations
- `p_value` is currently not computed (`null` with explicit reason).
- Price reconstruction from canonical events is simplified (bid/ask updates from event side and price field), so IC values are methodology-valid but sensitive to microstructure interpretation.
- No transaction cost, slippage, or fill model is included.
- IC is correlation quality only; IC does not imply deployable alpha after fees.

## Reference oracle parity
- Signal formulas in `examples/filtered_momentum.sig`:
  - `signal vol = rolling_std(mid(AAPL), 30)`
  - `signal filtered = if short_ma > long_ma && vol > 0.0 then raw / vol else 0.0`
- Current `differential_oracle_test` uses `bench/run_diff_oracle.sh --fixture synthetic_aapl --min-within-rate 0.999`.
- The fixture is generated by `test/reference_oracle/generate_fixture_events.py` and provides repeated AAPL signal-bearing rows, so the gate checks numeric oracle parity rather than only pipeline execution.
